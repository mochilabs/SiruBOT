# Component Views (Discord Components V2)

Views live as functions in `apps/bot/src/modules/general/view/`, or in `apps/bot/src/features/<name>/discord/views/` for feature folders (music, tickets, role-panels, games, custom-commands, greeting). Never write new views with legacy Embeds (`ExtendedEmbedBuilder`).

1. Start with helpers from `@sirubot/utils`: `createContainer()` (auto DEFAULT_COLOR accent), then `addSeparator(container)` and `createThumbnail(url)` — prefer these over `new`. Thumbnail+text combo: follow the `addTextWithThumbnail` pattern from `features/music/discord/views/play.ts` (SectionBuilder + setThumbnailAccessory; TextDisplay alone if no URL).
2. Assembly order: TextDisplay/Section → ActionRow (buttons/selects) → Separator → footer. Put buttons/selects inside `container.addActionRowComponents()`. Always send with `flags: [MessageFlags.IsComponentsV2]` — omitting it breaks rendering; check the call site too.
3. customId: never concatenate strings. Declare IDs once with `defineCustomId` (`lib/customId.ts`) in the owning module (`features/music/discord/customIds.ts`, `modules/general/customIds.ts`, `features/<name>/discord/customIds.ts`, or `lib/` when truly shared). The format is `{namespace}:v{version}:{action}[:{field}...]`; field kinds are `snowflake`, `uint`, `token`, `oneOf` and `nullable`, so values can never contain the `:` delimiter. The view calls `encode`, the handler's `parse()` calls `decode` and returns `this.some(...)` or `this.none()` (`decode` returns `null` for another namespace, another version, or malformed input; there is no legacy-format branch). Namespaces must be unique (`lib/customId.namespaces.test.ts` fails on a missing or duplicate declaration), and the worst-case length must fit 100 characters (checked when the declaration is created). Add a round-trip test that renders the view and feeds its IDs to the handler.
4. State: derive button disabled/emoji/labels from player state (paused, repeatMode, queue length, page bounds). Pagination: 5-item chunks (`QUEUE_PAGE_CHUNK_SIZE = 5`) + the `clampQueuePage` helper (`utils/queueViewId.ts`, the `queue:v1` declaration; queue view state lives in customIds, not on the player). Select option labels are capped at 100 chars — truncate via `formatTrack(..., { titleLength: { maxLength: 80 } })`.
5. Text: Korean; keep existing tone (`-#` subtext, `###` headings, emoji like 🎵📄🔇). Reuse `formatTrack` / `formatTime` / `formatTimeToKorean` / `getRequesterText` / `emojiProgressBar` / `volumeToEmoji` — don't create new formatters. One-line errors: `errorView(message)`.
6. Footer: playback views attach the `buildFooterSegments(player, volume)` pattern (playing server, volume, version).
7. Interactive messages that wait for presses (select/cancel, vote, paged panels): use `createComponentSession` (`lib/componentSession.ts`) instead of a hand-written collector; call `session.settle(reason)` where the flow ends, and put the "time ran out" edit in `onTimeout`.
8. Server settings actions: a new `settingsId` action needs one entry in `SETTINGS_ACTIONS` (`features/music/discord/interaction-handlers/settings.ts`: the screen to redraw plus an `apply`), plus the control in `features/music/discord/views/settings.ts`. Typecheck fails if the table lacks an action.

Deliver: complete view function code + a table of required flags/customIds at each call site (handler/command). Flag Discord limits up front if hit (5 buttons per row, 25 select options, 4000 chars text).
