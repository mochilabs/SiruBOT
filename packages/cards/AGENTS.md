# cards agent instructions (`packages/cards`)

Repo-wide rules live in the root `AGENTS.md`. Paths are relative to `packages/cards/src/`.

- Runtime-independent pieces of the Takumi cards: element helpers (`h`, `img`), design tokens (`tokens.ts`), pure artwork helpers (`artwork.ts`: letterbox detection, dominant color, color mixing, image header size) and `greetingCard`. data-api renders PNG via `@takumi-rs/core`; the dashboard renders PNG previews via `@takumi-rs/wasm` from the same nodes.
- **The root export must never import a node-only module** (`node:*`, `Buffer`, `@takumi-rs/core`, `fs`). The dashboard bundles it. Font file reading, native rasterizing, remote image downloads and icon paths stay in data-api `renderers/shared/takumiKit.tsx` and are passed in as data (fonts and image data URIs are the caller's job).
- `greetingCard(image, vars)` is a pure function that interprets the contract in `@sirubot/utils/memberGreeting` (1200x675 card, layer x/y in %, sizes in px, center anchor) and `greetingCardDesign` (preset gradients). Import utils through subpaths only. Colored emoji stay in the text and are rendered natively via `TwemojiMozilla.ttf` (`generic: 'emoji'`) in both data-api and dashboard.
- Changing a layout number in `greetingCard.ts` changes both the Discord image and the dashboard preview. `greetingCard.test.ts` pins the coordinate contract.
- Tests import this package from **source** through the root `vitest.config.ts` alias; apps' typecheck and build use `dist`, so run `yarn typecheck` after changing an export.
- Shape layers (`shape` in the greeting contract) render as inline SVG through `greetingShapes.ts` (`shapeSvg`): rect, circle, triangle, diamond, hexagon, star, heart, with optional rotation, corner radius, gradient, stroke, outline-only and blur (rotation and blur sit on the wrapper div, gradient/stroke inside the SVG). New optional fields must stay optional so saved v2 configs keep validating. Takumi native and WASM render these identically, but the dashboard resolves `@sirubot/cards` from `dist`, so rebuild it before checking the preview.
- Layer `animation` (float, drift, sway, spin, pulse, twinkle) is turned into closed CSS `@keyframes` by `greetingAnimations.ts` (`greetingAnimationCss`) and applied to an outer wrapper div with the same box as the layer (`withAnimation` in `greetingCard.ts`), so it multiplies with the layer's own rotation and opacity instead of replacing them. Rotation always uses three stops (0/180/360°): a two-stop 0→360 animation interpolates identical matrices and renders as a still frame. Layer periods are snapped to a divisor of the card loop length (the longest `durationMs`) and delays become negative phase offsets, so the animated WebP loops without a jump. Any new animation preset must close its keyframes (0% equals 100%) and be added to the `GREETING_ANIMATIONS` list in `@sirubot/utils/memberGreeting`.
- An animated GIF background (`background.dataUri` starting with `data:image/gif`) needs no card changes: Takumi plays it on the render timeline. `greetingAnimationDurationMs` (utils) then sets the card loop to a whole number of GIF loops (the closest to the longest layer period, at most 5 s), so layer periods snap to a divisor of the GIF length and the WebP loops cleanly. The dashboard and data-api read GIF timing with `parseGifDataUriTiming` (`packages/utils/src/gifTiming.ts`); image layers do not accept GIF.
- Text layers take optional effects: `weight` (400/600/700/900, wins over `bold`), `letterSpacing`, `lineHeight`, `maxWidth` with `overflow` (`wrap` default, or one-line `ellipsis`) and `maxLines`, `shadow` (omitted = the legacy drop shadow, `null` = none), `stroke` (`-webkit-text-stroke`) and `gradient` (`background-clip: text` with a transparent color). Avatar layers take optional `shape` (circle/rounded/square), `cornerRadius`, `ringWidth` (default 6), `shadow` and `glow` (one `box-shadow`). All fields are optional and a layer without them renders exactly as before (`greetingCard.test.ts` pins the old style). Takumi ignores `line-clamp` on these boxes, so `maxLines` is a `maxHeight` plus `overflow: hidden` instead. The server registers the variable Pretendard font, so any weight renders; the dashboard preview only has static subsets, so 400 and 700 (`PretendardJP-Regular/Bold.subset.ttf` in `apps/dashboard/public/fonts`, copies of `resources/fonts`) are fetched on demand by `ensureTextWeights` in `greeting-svg.ts`. Adding a weight step means a new subset file in both places.
